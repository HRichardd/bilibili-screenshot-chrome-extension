# Bilibili 原帧截图 · v0.2.2

扩展代码位于 `extension`。这是无需构建、无需依赖安装的 Manifest V3 原型。

## 加载

1. Chrome 打开 `chrome://extensions`；Edge 打开 `edge://extensions`。
2. 开启“开发者模式”，点击“加载已解压的扩展程序”。
3. 选择 **`F:\ai work space\bilibili screenshot\extension`**，不要选择上一级目录。
4. 点击扩展图标，在弹窗中点击“打开助手 / 设置”，选择并授权保存文件夹。
5. 刷新已经打开的 B 站视频页，然后使用 `Alt+Shift+S` 截图；也可在助手页选中视频，点击“截取所选视频”验证。

快捷键以浏览器实际注册结果为准。在弹窗或助手页点击“修改快捷键”，可通过浏览器原生管理页面修改。仅在浏览器获得焦点时触发，不是系统全局快捷键。也可在视频页点击扩展弹窗的“保存当前视频帧”。

## 当前约束

- 必须保留一个截图助手标签页，可以放在后台；重复助手页会提示使用原页。
- 仅支持 Bilibili 普通 `/video/` 页面。PNG 为当前视频流自然分辨率，无法提高源视频画质。
- 不截取网页播放器按钮、进度条或网页弹幕；视频内嵌字幕、游戏界面保留。
- 支持有限连续截图，同一视频页及助手总队列上限均为三张。每张请求获得队列位置后立即提帧，不等前一张写完才取画面。队列满时明确提示，不静默丢弃；PNG 写入按顺序串行执行。
- 单图上限 24 MiB PNG（32 MiB Base64）。超限不保存，可降低播放清晰度后重试。
- 目录句柄保存在当前设备扩展的 IndexedDB；重启后可能需要点击“重新授权”。不自动改存默认下载目录。
- 目录授权与截图内容不上传网络；不需要 Playwright、本地服务、账号系统。
- 分 P 切换时重新读取 video、标题和 URL 的 p 参数；网站不更新 p 参数的合集页面可能显示 P1，BV 和时间仍可区分。

## 更新代码

修改文件后在扩展管理页重新加载扩展，再刷新截图助手和 B 站视频页。更新时使用原目录重新加载，无需卸载；保留原扩展 ID 才能沿用已有目录句柄、浏览器配置。目录权限仍由浏览器决定，需要时在助手页重新授权。

## 从 0.1.0 更新后的快速检查

1. 重新加载原扩展，刷新助手和视频页；确认版本为 0.2.2。
2. 打开扩展弹窗，检查保存文件夹和实际快捷键是否正确。
3. 用弹窗按钮截图，再用快捷键截图。
4. 播放中适度连续触发，检查不同时间的画面分别保存，队列恢复到 0 / 3。
5. 关闭助手再截图，确认出现恢复提示；点击“打开截图助手”，必要时授权，再重试。

自定义文件夹只通过浏览器目录选择器授权，不支持手填绝对路径。成功提示在完整写入后显示；目录不可写时不会静默改存浏览器下载目录。

## 文件名

自动命名：`标题_BV号_P分集_视频时间_保存时间.png`。标题自动清理 Windows 不允许的字符并限制长度，重复名称追加编号，已有截图不会被覆盖。

## 开发检查

在项目目录执行：`node --test tests/core.test.mjs tests/background.test.mjs tests/assistant.test.mjs`。

## 保存失败验证

助手页底部展开“故障验证（可选）”，等待队列归零，点击“模拟下一次保存失败”，切回视频页只截图一次。应出现明确的“模拟保存失败”，且不创建本次图片文件；再截图一次应正常保存。测试只影响一次进入保存步骤的截图，可手动取消，刷新助手也会取消。

这验证失败反馈和恢复通道，不是实际磁盘故障测试。无需填满磁盘、修改系统权限或删除目录。关闭助手再截图可以另外验证助手断开时的恢复提示。

所有提示均在视频顶部显示。错误/队列满提示保留 7 秒；同时有成功提示时在错误下方排列，间距 12px，互不覆盖。错误消失后，成功提示自动回到顶部。
